# FFTPs 全局独立审计报告

- 审计日期：2026-11-09
- 代码版本：`d27132f`（`main`，工作区干净）
- 审计范围：`common`、`ipc`、`ftp`、`sftp`、`fftpd`、`fftp-http`（含 Web UI）、`debian`/`rpm`/`scripts`/`.github`，约 24.9k 行 Rust
- 审计方式：全量静态审读 + 关键路径交叉验证 + 本地构建/测试/Clippy/rustfmt 检查
- 限制：未做联网 CVE 库比对（本机无 `cargo-audit`/`cargo-deny`）、未做 Windows 运行时验证、未做动态渗透测试

## 一、总体结论

项目架构清晰，协议层与 Web 管理层边界明确；测试数量可观（333 个测试全部通过）；路径 jail、TLS、Cookie、IPC 权限等基础防护骨架存在。

但当前版本存在 **2 条可实际利用的越狱/本地接管链**，以及一组围绕「配额、连接计数、会话生命周期」的治理绕过。**不建议在公网或不可信多用户主机上直接部署**；局域网可信环境可有限使用，但应先修复 P0/P1。

| 级别 | 数量 | 摘要 |
|---|---|---|
| 严重 | 3 | SFTP 悬空符号链接逃逸；Windows 前缀比较越权；运行时目录/引导令牌本地劫持 |
| 高 | 8 | 配额不强制、连接计数可被瓦解、会话不失效、明文管理登录、Argon2 阻塞运行时、密钥权限等 |
| 中 | 12 | 死配置、热重载不生效、命令语义错误、同步 IO、CI 缺门禁等 |
| 低 | 6 | panic 边界、日志/配额统计漂移、审计缺口等 |

## 二、严重问题（P0）

### P0-1 SFTP：悬空符号链接可逃逸 home，在 jail 外创建/写入文件

- 证据：[sftp/src/path_resolve.rs](../sftp/src/path_resolve.rs) 第 694-696 行在 `canonicalize` 失败时无条件回退到 `validate_parent_and_build_path`；该函数第 601-610 行在父目录等于 home 时，只做字符串前缀检查并直接返回**未经 canonicalize、未检查末段符号链接**的路径；[sftp/src/file_ops.rs](../sftp/src/file_ops.rs) 第 83-105 行随后用 `OpenOptions::create` 打开该路径，POSIX 会跟随符号链接。
- 触发链：
  1. 用户在 home 内创建悬空绝对链接（见 P0-3 的 SYMLINK 缺陷），或共享目录中已存在指向已删除目标的链接；
  2. 对链接路径发送 `OPEN WRITE|CREATE`；
  3. `canonicalize` 因 `ENOENT` 失败 → 回退分支 → `open()` 跟随链接在 jail 之外创建文件。
- 影响：以服务账号权限在 home 外任意创建/写入文件，可投放 `~/.ssh/authorized_keys`、autostart、可写配置，构成真实越狱。
- 修复：回退分支对末段做 `symlink_metadata` 检查，`allow_symlinks=false` 时拒绝末段为链接；Unix 打开使用 `O_NOFOLLOW`；更彻底的做法是基于目录 fd 的 `openat2`/`cap-std` 严格模式。

### P0-2 Windows：路径前缀用字符串比较，可越权访问同名前缀兄弟目录

- 证据：[ftp/src/path_safety.rs](../ftp/src/path_safety.rs) 第 63-69 行、[sftp/src/path_resolve.rs](../sftp/src/path_resolve.rs) 第 64-69 行在 Windows 上把路径转小写后做**字符串** `starts_with`；FTP 在 `path_safety.rs` 第 217/232 行、SFTP 在 `path_resolve.rs` 第 372/622/649 行用于越界判定。
- 触发：Windows 下 home 为 `C:\Users\alice`，目标为 `C:\Users\alice2\secret`（或 `D:\share\alice-backup`）。字符串前缀判定通过。
- 影响：读写删/重命名同盘符下所有以 home 为前缀的兄弟目录，等价于跨用户越权。SFTP 侧需 `allow_symlinks=true` 且存在指向兄弟目录的链接；FTP 侧同理。
- 修复：统一改用 `Path::starts_with`/`strip_prefix` 组件级比较，删除字符串前缀实现。

### P0-3 运行时目录回退到可预测 `/tmp/fftpd-<uid>`，引导令牌可被本地劫持并接管管理员

- 证据：[common/src/paths.rs](../common/src/paths.rs) 第 90-96 行在 `XDG_RUNTIME_DIR` 缺失时回退到 `/tmp/fftpd-<uid>`；[fftp-http/src/setup.rs](../fftp-http/src/setup.rs) 第 42-53 行仅 `create_dir_all` + `fs::write`，不校验目录属主/权限，不使用 `O_EXCL|O_NOFOLLOW`；IPC socket 也位于同一目录（[ipc/src/transport.rs](../ipc/src/transport.rs) 第 119-134 行），只在 bind 后对 socket 设 0600。
- 触发：同机低权用户抢先创建 `/tmp/fftpd-<uid>`，把 `setup-token` 做成指向自己可读文件的符号链接；服务启动写入 256bit 令牌后，攻击者读取令牌并从回环调用 `/api/setup` 创建自己的管理员。也可替换/预占 IPC socket 冒充 fftpd。
- 影响：本地用户接管 Web 管理端与 FTP/SFTP 用户库，属于本地提权/横向移动。
- 修复：以 0700 创建并校验运行时目录属主与权限；令牌文件用 `O_CREAT|O_EXCL|O_NOFOLLOW` + 0600；优先要求 `XDG_RUNTIME_DIR`，否则使用 `/run/user/<uid>` 并校验。

## 三、高危问题（P1）

### P1-1 SFTP：SYMLINK 校验虚拟目标、落盘原始 target，`allow_symlinks=false` 可绕过

- 证据：[sftp/src/link_ops.rs](../sftp/src/link_ops.rs) 第 71-78 行只校验解析后的虚拟目标，第 126/163 行却用原始 `target` 创建链接。发送 `SYMLINK "/" -> "/rootlink"` 可通过校验，落盘为指向主机根目录的绝对链接。
- 影响：在共享目录植入指向主机文件系统的绝对链接，本地文件管理器/备份/索引工具、或被其他协议暴露时可能跟随，造成主机文件泄露/写入；也直接支撑 P0-1 的利用链。
- 修复：落盘使用校验后的 `resolved_target`（或 home 内安全相对路径），拒绝绝对 target；`allow_symlinks=false` 时禁止创建链接。

### P1-2 SFTP：配额只在 OPEN 预留 100MiB，写路径不校验，断连泄漏预留

- 证据：[sftp/src/file_ops.rs](../sftp/src/file_ops.rs) 第 122-144 行仅在 open 时预留 `QUOTA_RESERVE_BYTES`；写操作第 375-445 行无配额判断且允许任意 offset；[sftp/src/state.rs](../sftp/src/state.rs) 第 255-266 行会话清理直接 `drain()` 句柄，不结算也不回滚。
- 影响：有写权限的用户可写满磁盘；每次异常断连泄漏 100MiB 预留额度，可把同账号/跨协议配额耗死。
- 修复：按写入增量实时校验；cleanup/超时回收时结算实际大小并回滚预留。

### P1-3 SFTP：OPEN 先截断后检查配额，配额失败已造成数据丢失

- 证据：[sftp/src/file_ops.rs](../sftp/src/file_ops.rs) 第 83-90 行先 `truncate(true)` 打开；第 114-120 行在截断后才读取 `original_size`（恒为 0）；第 122-144 行配额不足时直接返回错误，但文件已被清空/创建。
- 影响：配额已满时打开已有文件并 `TRUNCATE`，原内容不可逆丢失；关闭时把整文件重复计为新用量，配额账目膨胀。
- 修复：先读原大小并做配额预检，再执行截断/创建；失败时保证无副作用。

### P1-4 FTP：配额固定按 100MB 预留、按实际字节结算且无上限复核

- 证据：[ftp/src/storage.rs](../ftp/src/storage.rs) 第 38 行 `ESTIMATED_MAX_FILE_SIZE = 100MB`，第 188-223 行固定预留后 `commit_usage` 实际字节；`commit_usage` 不做上限校验。
- 影响：配额 100MB 的用户上传 >100MB 单文件可远超配额；`REST` 大偏移 + `STOR` 可让 `set_len` 直接占盘；反之剩余配额 <100MB 时小文件也会被误拒。
- 修复：按 `REST 偏移 + 声明/实际大小` 预估，并在结算时按最终文件大小二次校验。

### P1-5 FTP：连接计数可被未登记请求瓦解；匿名别名造成永久泄漏

- 证据：[ftp/src/auth.rs](../ftp/src/auth.rs) 第 344-345 行 `reject` 无条件 `connections.unregister`，而登记发生在第 445 行；第 411-415 行「用户名非法」在登记前就调用 `reject`。第 452-469 行匿名会话以字面量 `"anonymous"` 登记，而 [ftp/src/listeners.rs](../ftp/src/listeners.rs) 第 115-140 行按客户端原始用户名/trace 注销，`ftp`/`ANONYMOUS` 等别名会漏注销。
- 影响：攻击者保持正常会话的同时，用非法用户名反复连接把该 IP 计数压到 0，绕过 `max_connections_per_ip`；匿名别名会话每次永久占用一个配额，默认 10 次后该 IP 无法连接，只能重启。
- 修复：只有登记成功后的失败才注销；登记/注销统一使用规范化用户名或 trace_id。

### P1-6 Web：管理员删除/改密不撤销既有会话；登录无速率限制；仅 api_token 时允许非回环明文登录

- 证据：[fftp-http/src/auth.rs](../fftp-http/src/auth.rs) 第 68-81 行会话只存用户名，第 152-165 行只做 `sessions.get`，从不校验管理员是否仍存在；第 194-215 行登录无失败计数/IP 限流；[fftp-http/src/config.rs](../fftp-http/src/config.rs) 第 400-408 行只要求「TLS 或 api_token 二选一」即可非回环启动，而 Cookie 的 `Secure` 仅由 `tls.enabled` 决定（`auth.rs` 第 186-191 行）。
- 影响：被删除/改密管理员的旧 Cookie 在 TTL（默认 12h）内仍可全权操作；管理员口令可在线爆破；仅配 api_token 时浏览器登录走明文 HTTP，口令与 Cookie 可被同网段嗅探。
- 修复：会话绑定管理员身份版本，变更时批量失效；登录按 IP+用户名限流/锁定；非回环存在 Web 登录时强制 TLS。

### P1-7 同步 Argon2 与同步文件 IO 阻塞 async 运行时（未认证 DoS）

- 证据：FTP 在 [ftp/src/auth.rs](../ftp/src/auth.rs) 第 477-495 行持 `StdMutex` 在 async 中执行 `users.reload`、`UserManager::authenticate`（Argon2id `m=65536,t=3,p=4`）并可能落盘；Web 登录 `fftp-http/src/auth.rs` 第 199-203 行同样同步校验。另有保存配置/用户、目录操作、日志读取等同步 IO 位于 async handler（`fftpd/src/control.rs`、`logs.rs`、`dirs.rs`、`fftp-http/src/routes.rs`）。
- 影响：并发 PASS 即可阻塞全部 tokio worker 并占用约 64MB/请求，形成低成本未认证 DoS；慢盘/NFS 时整站卡死。
- 修复：口令校验与文件 IO 全部放入 `spawn_blocking`，并对认证加独立并发/速率限制。

### P1-8 私钥/主机密钥权限不足

- 证据：[sftp/src/host_key.rs](../sftp/src/host_key.rs) 第 44 行 `tokio::fs::write` 直接落盘，未设权限；[ftp/src/cert_gen.rs](../ftp/src/cert_gen.rs) 第 46-53 行先写后 `chmod 0600`，存在短暂可读窗口；用户自带 FTPS 私钥不校验权限（`ftp/src/service.rs` 第 120-121 行）。
- 影响：同机其他用户可读取私钥，冒充服务器实施 MITM。
- 修复：Unix 下以 0600/目录 0700 原子创建并校验既有密钥权限。

## 四、中危问题（P2）

1. **SFTP 禁用用户不即时失效**：[sftp/src/state.rs](../sftp/src/state.rs) 第 108-144 行权限检查不读 `enabled`，缓存 TTL 固定 30s（第 23 行）。禁用用户可继续操作，权限回收最长延迟 30s。
2. **SFTP 单连接可无限开 session 通道**：[sftp/src/handler.rs](../sftp/src/handler.rs) 第 404-434 行对每个 channel 一律 accept 且无上限，未实现 `channel_close` 清理；`max_sessions_per_user` 只限制 TCP 连接。
3. **SFTP REMOVE/RENAME 跟随符号链接**：[sftp/src/dir_ops.rs](../sftp/src/dir_ops.rs) 第 137-143、243-284 行先 canonicalize 再删除/移动，客户端删链接实际删到目标；RENAME 的链接检查作用于已 canonicalize 路径，恒不生效。
4. **SFTP SETSTAT 可绕过配额并 chmod 0777**：[sftp/src/attr_ops.rs](../sftp/src/attr_ops.rs) 第 100-112 行只查 `can_write`，第 176-203 行允许任意 `set_len` 与 `0o777`。
5. **SFTP RMDIR 可删除 home 根**：[sftp/src/dir_ops.rs](../sftp/src/dir_ops.rs) 第 196-211 行 `"/"` 解析为 home，空 home 会被直接删除；删除前还对整棵子树递归统计。
6. **SFTP 扩展命令绕过限速**：[sftp/src/extended.rs](../sftp/src/extended.rs) 第 128-207 行摘要、第 209-260 行 copy-file 均未接 RateLimiter。
7. **SFTP 超大包只记 warn 不丢弃**：[sftp/src/protocol/utils.rs](../sftp/src/protocol/utils.rs) 第 16-18 行、[server/mod.rs](../sftp/src/protocol/server/mod.rs) 第 128-134 行，4 字节即可产生一条日志，可放大日志并造成流失步。
8. **FTP 主动模式无 PORT/EPRT 校验**：[ftp/src/active_mode.rs](../ftp/src/active_mode.rs) 第 59/91 行的校验函数无生产调用方；配置 `allow_nat_clients`/`validate_port_ip_reachable` 是死配置（[common/src/config.rs](../common/src/config.rs) 第 89 行）。启用主动模式后可被用于 FTP bounce/内网探测。
9. **FTP 单端口被动配置可 panic**：[ftp/src/service.rs](../ftp/src/service.rs) 第 342 行未校验 `passive_ports`，`start == end` 时 libunftp 取模 `range_size == 0` 会 panic；`start > end` 亦非法。
10. **热重载不更新限流/封禁策略**：`Fail2BanManager::update_config`、`ConnectionLimiter::update_config` 在生产代码中无调用；`FtpService` 在构造时按启动配置固化（`ftp/src/service.rs` 第 196-200 行），`fftpd/src/state.rs` 第 254 行只 stop/start 监听。
11. **配置项读取后未生效**：`max_log_size` 仅作为日志读取预算（[common/src/logging.rs](../common/src/logging.rs) 第 393/406 行），未做按大小轮转；`connection_timeout`、`default_transfer_mode`、`hide_version_info`、`max_login_attempts`、`sftp.log_level` 在实现中无引用。
12. **Web/守护进程若干管理面缺口**：
    - `SaveLogConfig` 可把 `log_dir` 指向任意目录并 `create_dir_all`，落盘前未跑完整 `Config::validate()`（[fftpd/src/logs.rs](../fftpd/src/logs.rs) 第 150-205 行）。
    - 目录创建/权限接口接受任意绝对路径并 `chown`/`chmod 0700`（[fftpd/src/dirs.rs](../fftpd/src/dirs.rs) 第 53-115 行）。
    - HTTP/TLS 无握手/读写超时与连接上限（[fftp-http/src/main.rs](../fftp-http/src/main.rs) 第 133-160 行）。
    - `SaveConfig` 先落盘再热重载，reload 失败不回滚（[fftpd/src/control.rs](../fftpd/src/control.rs) 第 170-185 行）。
    - 生命周期线程串行 mpsc 无超时，一次卡住后续控制请求全部挂起（[fftpd/src/state.rs](../fftpd/src/state.rs) 第 152-160、388-439 行）。
    - 多处锁 `.unwrap()/expect()`，一次 panic 毒化后持续失败。

## 五、低危与工程化问题（P3）

1. **UTF-8 切片 panic**：[common/src/users.rs](../common/src/users.rs) 第 167、469 行 `&content[..content.len().min(200)]` 可能在多字节字符中间截断而 panic（users.json 损坏/含中文时）。
2. **配额目录统计可被符号链接环拖死**：[common/src/quota.rs](../common/src/quota.rs) 第 265-278 行 `dir_size` 使用 `is_dir()`（跟随链接）递归，无深度/环检测。
3. **FTP 会话 IP 错配**：[ftp/src/auth.rs](../ftp/src/auth.rs) 第 132-135 行取 `last()`，第 151-160 行却 `remove(0)`；同名多 IP 登录时注销错位。
4. **Web 配置与令牌文件权限/原子性**：`fftp-http.toml` 以 umask 默认权限写入、非原子回写，含 api_token 与口令哈希（[fftp-http/src/config.rs](../fftp-http/src/config.rs) 第 207-219、266-267、314-315 行）。deb `postinst` 已对初始文件 `chmod 600`，但运行时保存路径未收紧。
5. **审计缺口**：系统服务安装/卸载接口未写审计（[fftp-http/src/routes.rs](../fftp-http/src/routes.rs) 第 506-518 行）；SSE 无连接上限，登出不断开已建立流。
6. **CI 门禁偏弱**：[.github/workflows/ci.yml](../.github/workflows/ci.yml) 第 7-9、40-41 行明确不跑 `cargo fmt --check`、Clippy 不加 `-D warnings`；全仓无 `cargo audit`/`cargo deny`；actions 使用版本 tag 而非 commit SHA；测试只在 Ubuntu 运行。

## 七、修复优先级建议

**立即（P0，阻断发布）**
1. 修复 SFTP 悬空链接回退：末段 no-follow + 不存在路径的父目录严格校验。
2. Windows 路径比较改为组件级 `Path::starts_with`（FTP/SFTP 共用实现）。
3. 运行时目录改为安全目录（0700 + 属主校验），令牌用 `O_EXCL|O_NOFOLLOW`。

**尽快（P1）**
